# Jev L0 路由接入设计

**状态：** 已确认，待实施
**日期：** 2026-09-21

## 目标

在保留现有 OpenAI 兼容模型 L1 → 复核 → L2 路由的前提下，接入
TypeSafe AI 的 Jev 作为 L0（Level 0）决策层：

- 对符合条件的简单题做风险分流。
- 仅对无图片的单选题和判断题尝试直答。
- 在 Jev 未达到置信度要求或不可用时，完全回退到现有路由。

Jev 不是自由文本生成模型，因此不用于填空、多选、图片理解或生成题目解析。
直答响应使用固定解析文本。

## 已确认的产品决策

| 决策 | 取值 |
| --- | --- |
| Jev 客户端 | 官方 Python SDK `typesafe-sdk` |
| L0 适用题型 | 无图片的 `single`、`judgement` |
| 直答门槛 | `0.990`（99.0%） |
| L0 解析文本 | `Jev L0 高置信度直答（99.0%+）` |
| L0 失败处理 | 无声回退，不改变现有成功/失败语义 |
| 测试 Key | 仅从剪贴板进入测试进程；不写入仓库、`.env`、日志或测试夹具 |

## 范围与非目标

本次包含：

- Jev 配置、客户端封装和 L0 路由。
- 单选题候选选项选择与判断题候选值选择。
- 现有静态风险规则、L1/复核/L2 流程的兼容回退。
- 离线单元测试和一次脱敏的真实 API 冒烟测试。

本次不包含：

- 用 Jev 替换 L1 或 L2。
- 图片题、多选题、填空题的 Jev 作答。
- 把 Jev 输出伪装成模型生成的长解析。
- 持久化、上传或记录测试 Key。

## 架构与数据流

在 `ModelRouter.solve()` 中保留现有的静态风险判断。静态风险已命中时，
继续直接调用 L2；此时不调用 Jev。这样能保持长题干、否定词、材料题和
未知题型的现有保守策略。

对于静态风险为空、没有图片、题型为 `single` 或 `judgement`，且能解析出
无歧义的有效选项集合的请求，L0 先发起一次 Jev System One 调用。无法解析
选项、判断题缺少两个判断选项或存在重复歧义时，直接回退旧路由。一次调用
包含两个 `Choice` 问题：

1. `candidate_answer`：从当前题目的预定义选项中选择候选答案。
2. `route`：在 `l0_direct`、`verify_l1`、`direct_l2` 中选择风险路由。

应用程序维护内部选项键到原始选项文本的映射。Jev 返回内部键后，服务将其
还原为输入中的原始选项文本；不修改 OCS 的 HTTP 响应结构，也不依赖 Jev
生成字符串。判断题同样从输入中的两个判断选项中选择，并还原原始文本。

路由规则如下：

```text
静态风险命中 / 不符合 L0 题型 / 有图片
  → 保持原有流程（静态风险直接 L2，其余走 L1 → 复核 → L2）

符合 L0 条件
  → Jev 返回 candidate_answer 与 route
    → route = l0_direct，且候选答案和路由的概率均 >= 0.990
      → 直接返回候选答案与固定解析
    → route = direct_l2
      → 直接调用现有 L2
    → 其他结果、低置信度或异常
      → 调用现有 L1 → 复核 → L2
```

L0 直答必须同时满足「候选答案正确」和「适合绕过 L1 复核」两个高置信度
条件。这样即使某个选项看似明确，Jev 仍可将存在语义陷阱的题目转交 L1 或 L2。

## 模块边界

新增 `jev_router.py`，职责限定为：

- 从环境变量创建 Jev 配置和官方 SDK 客户端。
- 根据题干、选项、题型构造 System One 的 `Choice` 问题。
- 校验 Jev 响应中的选项键、路由值和概率。
- 返回一个小型、与 OpenAI SDK 无关的 L0 结果对象。

`model_router.py` 继续负责总体路由、现有答案校验和 L1/L2 调用。它只消费
L0 结果，不了解 TypeSafe SDK 的响应对象。`main.py` 的 `/search` 成功响应
保持为 `code`、`question`、`answer`、`analysis` 四个字段。

## 配置与依赖

新增以下环境变量：

```dotenv
# 默认 false，确保未配置时行为与当前版本一致
JEV_ENABLED=true
TYPESAFE_API_KEY=仅在运行环境中配置
JEV_MODEL=jev-latest
JEV_DIRECT_CONFIDENCE=0.990
```

实现会将 `JEV_ENABLED` 默认设为 `false`。缺少 `TYPESAFE_API_KEY`、概率格式
非法或 SDK 初始化失败时，L0 视为不可用并回退；服务不能因为可选的 L0 集成
而无法启动。`pyproject.toml`、`uv.lock` 和 `requirements.txt` 会加入
`typesafe-sdk`，使 `uv` 与 `pip` 两种安装方式一致。

测试时不把剪贴板 Key 写入任何文件。实现完成后，真实冒烟测试会在单个子进程
中临时设置 `TYPESAFE_API_KEY`，进程退出后该变量随之消失。

## 错误处理、日志与数据边界

- Jev 网络错误、认证失败、超时、SDK 异常和响应结构异常均不向 `/search`
  暴露，直接使用现有模型路由。
- L0 仅记录路由、模型名和已归一化的概率；绝不记录 Key、Authorization 标头
  或完整 TypeSafe SDK 响应。
- 启用 L0 后，符合条件的题干和选项文本会发送给 TypeSafe AI；图片不会发送。
  这与当前向 OpenAI 兼容供应商发送题目是独立的数据流。
- Jev 的 `direct_l2` 建议会触发现有 L2 调用；其余非直答结果默认走既有 L1
  双调用验证，而不是将 L0 的错误转换为 HTTP 5xx。

## 测试策略

新增纯离线的 `unittest` 覆盖，使用假 Jev 客户端，不产生任何 API 消耗：

- 单选题和判断题在 `0.990` 边界直答，`0.989` 回退。
- 原始选项文本、判断选项文本及 OCS 响应字段保持兼容。
- `verify_l1` 与 `direct_l2` 两种 Jev 风险路由正确衔接旧逻辑。
- 图片、填空、多选、静态风险题不调用 Jev。
- 未配置 Key、SDK 失败、超时和无效响应不会破坏原有请求。
- 现有全部测试继续通过。

离线测试通过后，使用剪贴板中的临时 Key 对一个不含敏感信息的简单样例题
执行一次真实 API 冒烟测试。测试输出只报告成功状态、所选路由和已脱敏的
置信度区间，不回显 Key。

## 验收标准

1. 未启用 L0 时，现有服务行为和测试结果不变。
2. 启用 L0 后，只有满足全部条件的无图片单选/判断题可由 Jev 直答。
3. 直答的答案为原始选项文本，解析为已确认的固定文本。
4. 任一 L0 故障都能安全回退至旧路由。
5. 本地测试不读取真实 Key；真实冒烟测试不持久化或泄露 Key。
